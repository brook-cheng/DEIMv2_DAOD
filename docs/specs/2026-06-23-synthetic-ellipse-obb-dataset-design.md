# 合成椭圆 OBB 数据集：密度对照实验设计

> 创建日期：2026-06-23
> 目的：验证「数据集 GT 稀疏度」是否为 DEIMv2-OBB 分类 head 分数坍塌的根因（H1 假设）
> 状态：设计阶段，待评审

---

## 1. 背景与动机

当前 SP 数据集（2797 张图 / 3388 GT 框，平均 1.2 GT/图，中位数=1）训练后分类 head 输出分数全部挤压在 0–0.15 区间，TP/FP 无法区分，Precision=0.038。虽然 OBB_CODE_REVIEW.md 中 10/11 个 bug 已修复，但分数坍塌问题仍在。

需要排除一个最可能的假设：**数据集 GT 密度不足导致 300 个 query 中 99.6% 被分配为"无目标"，分类 head 无法获得足够正样本信号。**

本实验通过合成不同 GT 密度的椭圆数据集，对照短时训练后的分数分布，量化 GT 密度对分类 head 的影响阈值。

---

## 2. 实验设计

### 2.1 核心变量

| 变量 | 处理 |
|------|------|
| **GT 密度**（自变量） | 7 个梯度：1, 2, 5, 10, 20, 50, 100 GT/图 |
| **分数分布**（因变量） | `test_infer_diag.py` 输出的 score 直方图、mAP、P/R |
| **其他因素**（控制变量） | 相同模型结构、相同超参、相同训练 epoch 数、相同背景和外观 |

### 2.2 对照实验矩阵

实验编号 | GT/图 | 训练集 | 验证集 | 负/正比估算 | 预期观察
E1 | 1 | 400 | 100 | ~300:1 | 极端稀疏，模拟当前数据集。预期分数全部挤在 <0.15。
E2 | 2 | 400 | 100 | ~150:1 | 与当前数据集上限相当。
E3 | 5 | 400 | 100 | ~60:1 | 过渡带。
E4 | 10 | 400 | 100 | ~30:1 | 理论临界区。预期分数开始出现分散。
E5 | 20 | 400 | 100 | ~15:1 | 合理稀疏度。预期分数分布明显分离。
E6 | 50 | 400 | 100 | ~5:1 | 密集场景。
E7 | 100 | 400 | 100 | ~2:1 | 极度密集。H1 成立时预期分数分布健康，作为上界参考。

- 总计：7 × 500 = 3500 张图
- 训练超参：固定使用 `deimv2_obb_sp.yml` 配置（除数据集路径外），30 epoch
- 每实验使用独立的 `opencode.jsonc` 训练配置、独立日志

### 2.3 判定标准

| 观察 | 结论 |
|------|------|
| 从某个密度阈值开始，score 分布出现 >0.3 的明显峰值 | **H1 确认** — GT 密度是该阈值以下的主因 |
| 全部 7 组均分数坍塌 | **H1 排除** — 问题在 loss / decoder / Kendall，继续 H2-H4 诊断 |
| 分数分离但 mAP 仍然低 | 问题从「分数坍塌」转移到「分数排序」，需排查 MAL soft target |

## 3. 数据集规范

### 3.1 目录结构

```
synthetic_ellipse/
  classes.txt                        # r, g, b (每类一行)
  density_001/
    train/                           # 400 张 PNG + 400 个 DOTA txt 标注
    val/                             # 100 张 PNG + 100 个 DOTA txt 标注
  density_002/
    train/
    val/
  ...
  density_100/
    train/
    val/
```

### 3.2 图像参数

| 参数 | 值 |
|------|-----|
| 尺寸 | 256 × 256 px |
| 通道 | RGB 3 通道 |
| 格式 | PNG |
| 背景色 | 随机灰度 `(v, v, v)`，`v ∈ [50, 200]` 均匀采样，每图不同 |

### 3.3 椭圆参数

| 参数 | 范围 |
|------|------|
| 短轴 2a | [20, 60] px，均匀随机 |
| 长轴 2b | [40, 100] px，均匀随机 |
| 长宽比 b/a | ≥ 1.5，不满足则重采样 |
| 旋转角 θ | [0, π) 弧度，均匀随机 |
| 中心 (cx, cy) | [0, 255] 随机，带碰撞检测 |

### 3.4 颜色规范（3 类）

类别 | 颜色标识 | RGB 范围
r（红椭圆） | 红色系 | `(R, G, B) ∈ [(170, 10, 10), (230, 30, 30)]`
g（绿椭圆） | 绿色系 | `(R, G, B) ∈ [(10, 170, 10), (30, 230, 30)]`
b（蓝椭圆） | 蓝色系 | `(R, G, B) ∈ [(10, 10, 170), (30, 30, 230)]`

各通道在范围内独立均匀采样，加 ±5 的像素级噪声模拟光照变化。

填充方式：非抗锯齿实心椭圆（`cv2.ellipse`，`thickness=-1`），确保边界清晰。

### 3.5 碰撞检测

- 两两椭圆的**最小外接旋转矩形**之间的 IoU（Intersection over Union，使用精确多边形 IoU 或简化旋转矩形 IoU）< 0.05
- 椭圆整体必须完全在 [0, 255] 范围内（OBB 四个顶点均不越界）
- 若随机采样 N（目标 GT 数）次后无法放置所有椭圆，则重新生成整张图
- 碰撞检测使用精确**多边形 IoU** 计算（将 OBB 转换为 4 顶点多边形求交），确保标注质量

### 3.6 标注格式（DOTA）

每张图对应一个同名 `.txt` 文件，每行一个 GT。格式遵循 `DotaDataset` 的实际解析逻辑（`engine/data/dataset/dota_dataset.py:102-114`）：

```
x1 y1 x2 y2 x3 y3 x4 y4 category_name difficulty
```

字段说明：

| 字段 | 说明 |
|------|------|
| `x1 y1 x2 y2 x3 y3 x4 y4` | OBB 的四个顶点，像素坐标（浮点数），顺序为顺时针或逆时针均可（内部会通过 `xyxyxyxy_to_xywhr` 自动转换为 `(cx,cy,w,h,θ)`） |
| `category_name` | 类别名，与 `classes.txt` 中的行一致：`r`、`g` 或 `b` |
| `difficulty` | 一律填 `0`（本实验无难例） |

> 注意：不是 `(cx, cy, w, h, θ)` + `category_id` 格式。`DotaDataset` 读取的是 DOTA 原生格式：**8 个顶点坐标 + 类别名 + difficulty**。内部通过 `xyxyxyxy_to_xywhr()` 转换为模型所需的 OBB 表示。

示例（一个椭圆）：
```
128.0 80.0 178.0 90.0 168.0 140.0 118.0 130.0 r 0
```

### 3.6.1 顶点生成

椭圆的 OBB 四个顶点由椭圆参数直接计算：

```python
# 输入：cx, cy, a（半短轴）, b（半长轴）, theta（弧度）
# 输出：四个顶点 (x_i, y_i)

# 未旋转时 OBB 四个角点（相对于中心）
corners_local = np.array([
    [-a, -b], [ a, -b], [ a,  b], [-a,  b]
])

# 旋转矩阵
cos_t, sin_t = np.cos(theta), np.sin(theta)
R = np.array([[cos_t, -sin_t], [sin_t,  cos_t]])

# 旋转 + 平移 → 像素坐标四个顶点
vertices = corners_local @ R.T + np.array([cx, cy])
# → vertices.shape = (4, 2)，按顺时针排列
```

### 3.6.2 classes.txt

```text
r
g
b
```

类别顺序决定 `cat_id`：r=0, g=1, b=2。

### 3.7 类别分配策略

- 密度=1 时：全部使用类别 `r`（最简场景验证分类基础能力）
- 密度≥2 时：三类等概率轮转分配：`r` → `g` → `b` → `r` → ...
  例：密度=5 → 类别分布为 r,r,g,g,b（近似 2:2:1）

### 3.8 训练超参（统一配置）

```yaml
# 伪码：除数据集路径外与 deimv2_obb_sp.yml 一致
epoches: 30
batch_size: 6
img_size: 256×256
lr: 5e-4 (backbone 1e-5)
KendallWeighting: enabled
DEIMCriterion:
  weight_dict: {loss_mal: 1, loss_bbox: 2, loss_kld: 2, loss_fgl: 0.2}
  gamma: 1.5
  alpha: 0.75
增广策略：
  训练期：Mosaic(p=0.5) + RandomPhotometricDistort(p=0.5) + Flip + Resize[256,256] + Normalize
  验证期：Resize[256,256] + Normalize
```

> 注意：Mosaic 在 GT≤2 的超稀疏场景下，4 图拼接后 GT 总数最多 8，仍然远低于 300 个 query。这在 E1/E2 中会是一个有趣的子观察——Mosaic 是否能在稀疏场景中缓解负样本比例过大的问题。

### 3.9 生成依赖

- Python `opencv-python` >= 4.5（`cv2.ellipse`）
- Python `shapely` >= 2.0（OBB 多边形 IoU 碰撞检测）
- `numpy`

## 4. 实验执行流程

### 4.1 阶段〇：数据样例审查（闸门）

**在生成完整 3500 张数据集之前**，先小批量生成 50 张样例：

1. 覆盖全部 7 个密度梯度（每个梯度 ~7 张，确保每个密度都有样本）
2. 输出目录：`synthetic_ellipse/samples/`
   - 每张图同时输出三份：原图 PNG、标注 TXT、可视化叠加图（椭圆 + OBB 外接框）
3. 审查重点：
   - 椭圆颜色是否可区分（红/绿/蓝）
   - OBB 标注是否紧密贴合椭圆
   - 碰撞检测是否生效（无重叠椭圆）
   - 高密度场景（50、100 GT/图）下是否因碰撞检测导致图像过满或无法放置
4. **闸门规则**：审查通过后才继续 4.2 阶段的大批量生成。不通过则调整生成参数后重新生成 50 张样例，直到审查批准。

### 4.2 阶段一：数据集生成（一次性）

1. 实现 `scripts/generate_synthetic_ellipse.py`
2. 输入：密度值列表、输出根目录
3. 输出：7 组数据集，每组 train 400 + val 100
4. 验证脚本：`scripts/validate_synthetic_dataset.py`
   - 校验每张图的 GT 数量是否匹配目标密度
   - 校验 OBB 无重叠（IoU < 0.05）
   - 校验无越界标注
   - 输出 `dataset_stats.json` 统计摘要

### 4.3 阶段二：批量短训练（7 个并行实验）

每实验：
1. 从 `configs/custom_obb/deimv2_obb_sp.yml` 复制配置
2. 修改 `train_dataloader.dataset.img_folder` 和 `ann_folder`
3. 修改 `img_size` 为 `[256, 256]`
4. 修改 `epoches` 为 `30`
5. 设置 `output_dir` 为独立目录
6. 运行：`python train.py --config configs/custom_obb/synthetic_exp_<N>.yml`

使用 Comet 记录以下指标：
- `val_precision`、`val_recall`、`val_AP50`、`val_mAP`（每 epoch）
- `loss_fgl`、`loss_mal`（每 batch，采样每 100 step）

### 4.4 阶段三：推理诊断（每实验）

每实验训练完成后：
1. `python test/test_infer_diag.py --ckpt <path> --config <path> --num 20`
2. 收集每组 `score_dist.txt` 的分布直方图
3. 绘制 **密度-分数分布曲线**：横轴=GT密度，纵轴=score分位数，每组一条线

### 4.5 预期时间估算

| 步骤 | 耗时（估） |
|------|-----------|
| 阶段〇：样例生成 + 审查 | ~5 分钟 + 审查时间 |
| 阶段一：数据集完整生成 | ~10 分钟 |
| 阶段二：7 组训练（各 30 epoch, 1–2×GPU） | 串行 ~4 小时 / 并行 ~2 小时 |
| 阶段三：推理诊断 | ~10 分钟 |
| 合计 | ~2.5–4.5 小时（不含审查等待） |

## 5. 分析计划

### 5.1 主要图表

1. **分数分布热力图**：7 行 × 20 bin 的热力图，X 轴 = 分数区间 [0, 1]，颜色 = 预测数
2. **密度-分数分位数曲线**：多线图（P10, P25, P50, P75, P90, P95）
3. **密度-mAP 散点图**：验证 H1 的定量关系
4. **损失曲线对比**：7 组 `loss_fgl` 趋势叠加图

### 5.2 决策路径

```
所有组的 score 分布
         │
    ┌────┴────┐
    │         │
 高密度组   全部组
 正常分离   分数坍塌
    │         │
    ↓         ↓
 H1 确认   H1 排除
    │         │
    ↓         ↓
阈值分析：  继续诊断：
哪一组开始  H2: MAL loss 参数
出现分离？  H3: Decoder 结构
           H4: Kendall 偏斜
```
