The ``decouple_angle=True`` reference path is deliberate and finite. The 5th
reference dimension (theta) is CONSUMED by MSDeformableAttention as angle —
it is NOT ignored. The 6-dim ADR -> 5-dim OBB transition across decoder
layers is the intended design and converges to the same rotated-sampling
semantics inside MSDeformableAttention.

EVIDENCE 1: MSDeformableAttention reference_points handling
--------------------------------------------------------------------------------
File: engine/deim/dfine_decoder.py:119-206 (MSDeformableAttention.forward)

MSDeformableAttention branches on ``reference_points.shape[-1]``:

  == 2  (line 150-158):  pure (x, y) center sampling, axis-aligned.
  == 4  (line 159-168):  (cx, cy, w, h) — center + wh-scaled axis-aligned
                         offsets. Uses dims [0:2] as center, [2:4] as wh.
  == 5  (line 169-199):  (cx, cy, w, h, theta) — OBB. 5th dim is theta in
                         [0, 1], scaled to [0, pi] at line 177:
                           angle = reference_points[..., 4:5] * torch.pi
                         Builds a per-head rotation matrix from angle,
                         rotates sampling offsets, samples at rotated locs.
                         => 5th dim IS CONSUMED as angle. NOT ignored.
  == 6  (line 169-175):  (cx, cy, w, h, eps, eta) — ADR external rect +
                         vertex offsets. Converted to 5-dim OBB via
                         external_rect_to_oriented_box at lines 172-175,
                         then same path as == 5.
  else  (line 201-206):  raises ValueError. Only 2, 4, 5, 6 are valid.

KEY FINDING: dims beyond xywh are NOT ignored. The 5th dim is consumed as
theta (angle) and directly affects sampling locations via the rotation
matrix. A 5-dim OBB ref and a 6-dim ADR ref both converge to rotated
sampling.

EVIDENCE 3: No scalar theta passed into spatial ADR offset branch
--------------------------------------------------------------------------------
The plan Todo 7 question: "does layer>0 ref_offset_detach = inter_ref_bbox.detach()
pass scalar theta into a branch that expects spatial ADR offsets?"

Answer: NO. At layer > 0, ref_offset_detach is 5-dim OBB (cx, cy, w, h, theta),
NOT 6-dim ADR (cx, cy, w, h, eps, eta). MSDeformableAttention's == 5 branch
expects exactly this — (cx, cy, w, h, theta) — and consumes theta as angle.
There is no dimension mismatch and no semantic mismatch. The 5-dim OBB is the
correct representation for the offset attention path at layer > 0, because
the layer-0 ADR -> OBB conversion (via external_rect_to_oriented_box) is
irreversible in the reference path (the offsets have been consumed to produce
theta). Subsequent layers refine the OBB reference directly.

to MSDeformableAttention via ref_offset_input, which correctly handles
the == 5 case.
